# Forever Anvil addon

The site's prices inside the game. Version 1 is a read-only helper (see [docs/addon-plan.md](../docs/addon-plan.md)):

- **Tooltips:** market and lowest price on your auction house, sold per day, region median, disenchant value, vendor price, data age.
- **Auction house (Browse):** tags listings worth buying to sell to a vendor (`Vendor +X`) or to disenchant (`DE +X`).
- **Profession window:** profit per craft next to each recipe.
- **Settings:** Esc → Options → AddOns → Forever Anvil, or `/fa options`. `/fa` shows which house you're on.

Version 2 adds personal tools (plan milestone A3):

- **Upgrades:** `Upgrade +X` on tooltips and auction rows, from your equipped gear, class and level (`M.UpgradeFor`, a port of `src/lib/upgrades.js`).
- **Leveling helper:** `skill-up` on the known recipe with the cheapest reagents per expected skill point (`src/lib/levelmath.js` rule; each recipe's yellow and grey skill ship in the data).
- **Waylaid crates:** Favor and cheapest fill on the crate's tooltip (`src/lib/cratemath.js`).
- **Watchlist and shopping list:** kept in game (each window has an editor; Alt-click watches an item; the bag button right of Create All in the profession window adds a recipe's reagents for the number in the quantity box), or imported from the site's "Copy for the addon" buttons (`src/lib/addonstring.js`) with `/fa import`, or `/fa watch <item> [price]` in game. `Target` and `Need X` tags in the auction house; `/fa list` and `/fa watch` open their windows.
- **Prices window** (`Prices.lua`, `/fa prices [search]`): the site's `/prices` page in game. Search, categories and sorting are `M.PriceRows` (tested against the page's rules); item names, quality, category and icons ship in the data (`items`, `encodeItems` in `pipeline/addon-data.js`, about 280 KB for Europe), because the game only knows the names of items it has loaded.
- **Minimap button and menu** (`Minimap.lua`): status, lists, quick switches and settings. The crest texture `ForeverAnvil/Media/Icon.tga` is made from `public/img/logo.svg` by `node tools/addon-icon.js` (the game loads TGA, not PNG or SVG).
- **Old price notes** (`Freshness.lua`): a chat note at login when the prices are over a day old, and when a copy in your guild or group has newer ones (copies send each other the time of their prices on the hidden addon channel, prefix `ForeverAnvil`, message `1:<unix time>`).

Version 2.1:

- **Bag value** (`Bags.lua`, `/fa bags`): every item in your bags at its best use, `M.BestUse` (auction house after the cut, disenchanting, or a vendor; soulbound items skip the auction house).
- **Translations** (`Locale.lua`, `Locales.lua`): `ns.L["English text"]` gives the client's language (German, French, Spanish) or the English. Add a text: wrap it in `L[...]` and add it to every table; `npm test` fails when a language is missing one or a translation's placeholders differ. On those clients the prices window asks the game for its item names (`C_Item.RequestLoadItemDataByID`) and searches both.

Version 2.2:

- **Upgrades window** (`Upgrades.lua`, `/fa upgrades`): `M.SpecUpgrades` ranks gear by stats for your talent spec (`M.SPECS`: rough weights per class and tree; `M.SpecIndex` picks the tree with the most points). Item stats come from the game (`C_Item.GetItemStats`, after `RequestLoadItemDataByID` for items it hasn't loaded), parsed by `M.ParseItemStats`. Without that API it falls back to item level with `M.FindUpgrades`, a port of `findUpgrades` in `src/lib/upgrades.js` (tested against it). The gear details (subclass, slot, item level) ship in the data as `gear` (`encodeGear` in `pipeline/addon-data.js`, about 100 KB for Europe).

Version 2.5:

- **Auction house scan** (`Scan.lua`, `/fa scan` or the Scan button under the auction house): one `C_AuctionHouse.ReplicateItems` request (the game allows one every 15 minutes), then `GetReplicateItemInfo` is read 1,000 auctions per frame and summed up by `M.Aggregate`, a port of `aggregate` in `src/lib/pricemath.js` (tested against it). The result is saved per house in `ForeverAnvilDB.scans` (`"EU:113"`, in the shipped house format) and `ns.ScanOf` lays it over the shipped prices while it is newer (`M.MergeScan`: scanned items take the new min, market, quantity and listings and keep the shipped sold per day). `ns.DataAge` then reports the scan's age.
- **Bag value ignore list** (`Bags.lua`): right-click a row to leave the item out (`ForeverAnvilDB.bagIgnore`, by item ID, for every character); "Show ignored" lists those items greyed out under the rest.

## Releases

`.github/workflows/addon.yml` publishes a new version 4 times a day, with fresh prices, to CurseForge (project 1823345) and Wago (project 96EX0jNg). You can also start it by hand under Actions → "Addon release".

- **Version:** `addon/VERSION` plus the build time, e.g. `1.0.202611221340`. Raise `VERSION` (and add notes to `addon/CHANGELOG.md`) when the addon's code changes.
- **How:** `tools/addon-release.sh` stages the addon and that run's data in `build/addon-src` as a throwaway git repo tagged with the version. The [BigWigs packager](https://github.com/BigWigsMods/packager) needs a tag to upload a "release" rather than an "alpha", and it skips files git doesn't track, like the price data. The packager then zips it and uploads it.
- **Secrets:** `CF_API_KEY` and `WAGO_API_TOKEN`. Without one, that site is skipped; the zip is still kept on the run's page for 7 days.
- **Dry run on your own computer:** `node pipeline/addon-data.js --live`, then `bash tools/addon-release.sh`, then the packager's `release.sh -d -t build/addon-src` (`-d` means don't upload).

## Try it in game

1. Build the data from the live site: `npm run addon -- --live` (add `--region=eu,us` for both regions).
   Plain `npm run addon` builds from `./out` instead, but a local `npm run prices` has no sales history, so "sold per day" stays empty.
2. Copy `addon/ForeverAnvil` and `addon/ForeverAnvil_Data_EU` into the game's `Interface/AddOns` folder.
3. In game: `/fa` should name your ruleset and house. If it asks, set it with `/fa ruleset PvP` (or Normal, Roleplay, RP-PvP).

## The Forever client (confirmed in game, 2026-11-22)

- Interface `16001`, build 71037. It's built on the modern game engine with the old world's content, so it has the modern APIs and windows, not the classic ones.
- Tooltips use the modern tooltip system (`TooltipDataProcessor`). There's no global `GetItemInfo`, only `C_Item.GetItemInfo`; expect other classic globals to be missing too.
- The profession window is the modern one (`Blizzard_Professions`): profits come from `C_TradeSkillUI.GetRecipeSchematic`, and rows from the recipe list's `ScrollBox`.
- The auction window is the modern one (`Blizzard_AuctionHouseUI`). Its browse rows get only an index, which the addon looks up in the list. The window's code can load before the list is set up, so the addon hooks windows when they open (`AUCTION_HOUSE_SHOW`, `TRADE_SKILL_SHOW`) and never asks the list for rows before it's ready.
- The auction house scan works (confirmed 2026-11-24): `C_AuctionHouse.ReplicateItems` and `REPLICATE_ITEM_LIST_UPDATE` exist, and `GetReplicateItemInfo` returns count 3rd, buyout 10th and item ID 17th, counted from 0. The Scan button sits on the tab row, at the window's bottom right.
- The classic windows are still supported, in case another client uses them. `/fa debug` shows which windows and hooks are in use.

## Not checked in game yet

- Guessing the ruleset from the realm name (so far it's been set by hand with `/fa ruleset`).
- The neutral (Blackwater) house, used while you're at the auction house in Stranglethorn, Tanaris or Winterspring.
- Vendor-flip tags (none were on the market while testing; disenchant tags are confirmed).
- All of version 2: which profession-info call gives your skill (`GetChildProfessionInfo`, then `GetBaseProfessionInfo`), that recipe IDs are spell IDs (the shipped skill levels are keyed by spell), equipped item levels from `GetInventoryItemLink`, `GetItemCount` counting the bank, the `BasicFrameTemplateWithInset` windows, the shopping list's click-to-search, Alt-click to watch (hooks `HandleModifiedItemClick`), shift-click into the windows' item boxes (hooks `ChatEdit_InsertLink`), the "Add to shopping list" button beside the craft buttons, the prices window (item icons from shipped file IDs, the `UI-SortArrow` and scroll-knob textures, mouse-wheel scrolling), the list rows' pencil and X textures, and the minimap button (the TGA icon, its position on this client's minimap, the menu closing when you click elsewhere).
